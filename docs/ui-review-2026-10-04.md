# Calino UI review — 4 October 2026

The visual direction is worth keeping: warm paper, Newsreader headings,
muted calendar colours, an editorial journal, and a single action pill that
continues between screens and modals. The main problem was that surrounding
chrome sometimes attracted more attention than the person's content.

## Criticisms and changes

| Observation | Design decision and implementation |
| --- | --- |
| The sidebar stacked a rounded outer panel, rounded navigation groups, borders, selected-row fills and accent rails. Too many edges for a short destination list. | Remove the navigation group fills and borders. Keep group spacing, labels and animated selected rows. Reduce the sidebar's light shadow from 18dp to 12dp. |
| Light copper was attractive as decoration but too faint on small action labels and selected controls. It measured about 3.36:1 on the canvas and 2.91:1 on AccentSoft. | Deepen light Accent from `#B07D4F` to `#8D5D38`: about 5.27:1 on Canvas and 4.56:1 on AccentSoft. Keep the existing dark copper and stored calendar colours. Guard accent labels and on-accent text in the palette tests. |
| Pure white cards looked colder than the warm canvas. | Use an ivory Panel and matching light on-colours (`#FFFDFA`). This changes shared surfaces throughout Settings, Tasks, Journal, menus and editors. |
| Floating controls had a broad shadow. The initial 92% fill made the glass feel too opaque, as the user pointed out. | Restore the original 68% translucent fill and sampled blur for both root and modal pills. Keep the lighter 8dp shadows. Render menu labels at full foreground opacity and secondary icons at 70%; test labels and icons over bright and dark backdrops. |
| Appearance offered three choices but clipped Dark at ordinary phone width. A basic preference should be visible without discovering a sideways scroll. | Fit all three cards to the available width. Their preview marks also adapt. Add a device regression test for complete visibility and Dark selection surviving navigation. |
| Context-menu actions lacked Calino's press feedback; the menu also drew a shadow in dark mode despite the flat-dark design rule. | Use shared animated press feedback, merged action semantics, a shared corner token and a smaller, theme-gated shadow. Let rows grow when their labels wrap. |
| Journal list cards repeated a date dot and a cryptic word-count badge such as `8 W`. These distracted from very short entries and consumed vertical space. | Remove the repeated dot and word-count badge from the list. Use a finer spine and a two-line excerpt with a smaller title-to-excerpt gap. Keep word counts in the reader/editor, and give journal cards shared press feedback. |
| Filter and editor chips painted compactly but offered only a 36dp custom touch target. | Keep the painted chip compact inside a 48dp interactive lane. Merge its text into the outer semantics and extend the existing task-date test to assert the lane's height. |
| The sidebar's Today action used the wall clock while the rest of sample mode showed frozen May dates. | Read Today and its highlight from `LocalCalinoNow`, matching the calendar and journal. Connected-account mode continues to use the live clock. |

The contrast floor follows [WCAG's small-text requirement](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
The chip geometry follows [Android's guidance to separate compact visuals from touch targets](https://developer.android.com/develop/ui/compose/accessibility/api-defaults).
These checks cover named colour pairs, not a claim that every rendered screen
is fully accessibility compliant.

The pill material was revised after user feedback: transparency and the visible
blur are part of Calino’s preferred character. Foreground readability is handled
without covering up that material.

## Interaction ownership

No recurrence, data ownership or write path changes. Menu swipe
arbitration remains in `CalinoActionMenu`; modal scrolling/dismissal stays in
`SwipeDownDismiss`; journal paging remains a card per `HorizontalPager` page.
The new press feedback uses the existing click recognizer and `CalinoMotion`.
The glass sampling and root/modal pill ownership handoff are preserved.

## Other design observations

- Seven-day Range is necessarily compressed on a phone: many titles and
  locations are truncated. The existing 1/3/7 control is the useful escape
  hatch. Dense timeline content would benefit from a separate information
  hierarchy pass rather than shrinking text further.
- The icon-only dock and its hold/scrub gestures take learning. Its current
  compactness is visually strong, but destination labels or contextual
  onboarding could improve first-use comprehension.
- Full editors expose many calendar options. Progressive disclosure could
  make the first screen calmer, but needs a focused workflow review so it
  does not bury frequently edited fields or add extra taps.
- Serif titles and time heroes are effective. Additional bouncy motion or
  decorative gradients would compete with that quiet identity. Keep routine
  transitions restrained and reserve expressive motion for small controls.

## Validation

Five existing assertions failed identically on the unchanged `9fda7a2`
checkout: two task-completion assertions ignored the five-row Completed
preview, two navigation/dismissal assertions assumed a below-fold task was
mounted, and one sidebar assertion hard-coded September. Completion checks
also used an obsolete checkbox description instead of the row's full
date/category/completed semantics. They now select the Completed filter,
wait for the completion to settle, scroll to content, assert the restored
list/filter, and use the fixture date for Today.

Validation passed:

- `./gradlew test lintDebug assembleDebug`, including all 16 palette tests.
- 67 instrumented tests across SettingsRetentionTest, TaskInteractionTest,
  JournalFlowTest, PillMenuTest, ModalDismissalTest and NavigationDestinationsTest.
- Rendered light/dark review of the calendar, sidebar, journal, settings,
  event detail and action menu, including intermediate event-enter frames.
- HTML browser checks for all twelve screenshot pairs, theme switching,
  slider interaction and a 390px mobile layout without horizontal overflow.
- `git diff --check`.

All device work used only the API 36 emulator pinned to `emulator-5554`.
The complete instrumented suite and physical phones were not run in this pass.

The subsequent transparency revision passed 11 focused emulator checks: nine
pill interaction tests and two light/dark capture runs. Unit tests, lint and the
debug build passed again. The refreshed screenshots
and event-enter frames were inspected, and the HTML browser checks passed again.
The existing glass contrast test now checks full-opacity labels at 4.5:1 and
secondary icons at 3:1, including a pure-white backdrop. The 67-test result
above belongs to the initial refinement; that entire selection was not repeated
for this material adjustment.
